# 远程通知广播

远程通知是一条不发版就能全网弹窗的通道。维护者把 `notice.json` 推到主仓 `master` 的 `data/` 目录，所有安装包下次打开 App 时就会拉到并按规则弹窗；把文件删掉（或推一个移除提交），全网立即停用。整条通道只依赖 GitHub 仓库本身——没有推送服务、没有推送平台、没有自己的服务器。客户端走的是和课表数据热更同一条 raw + 镜像加速链路。

代码入口在 `data/Notice.kt`（解析与选取）和 `MainActivity.kt`（启动拉取与弹窗）。每次推送会先过 CI 的格式校验（`scripts/check_notice.py`），内容错误在推送时红灯拦下，而不是等 App 端静默降级——`message` 缺失等于整条不弹、日期写错等于排期失效，这些在用户端都无感知。

## 文件位置

```
https://raw.githubusercontent.com/yi-san-spce/ccsut-kb/master/data/notice.json
```

与课表数据热更清单 `latest.json` 同目录。镜像全挂时客户端自动退直连，和更新通道的行为一致。

## 文件格式

推荐数组形态，一次可以带多条通知：

```json
{
  "notices": [
    {
      "id": "2026-10-maintenance",
      "priority": "critical",
      "title": "教务系统维护",
      "message": "10 月 20 日 0:00-6:00 教务系统维护，个人课表暂时无法登录。",
      "startAt": "2026-10-19 08:00:00",
      "endAt": "2026-10-20"
    }
  ]
}
```

只发一条时可以省掉数组，直接把字段写在顶层：`{"title": "...", "message": "..."}`。

| 字段 | 必填 | 作用 |
|---|---|---|
| `message` | 是 | 正文。缺失或空白会被客户端整条跳过 |
| `id` | 否 | 去重键。缺省由内容自动派生，改文案即换 id，`once` 类会重新弹一次 |
| `title` | 否 | 标题，缺省「通知」 |
| `url` | 否 | 用户点主按钮时用浏览器打开，只接受 http/https |
| `link` | 否 | 点主按钮后在 App 内跳转，不开浏览器。现支持 `personal-login`：直达教务登录/同步页（打开即自动探测 CAS 会话，仍有效就免验证码直接拉课表，失效才要求短信验证码登录）。`1.2.0-beta.4` 起支持；旧版本忽略此字段并回退 `url`，两者都没写时按钮只关闭弹窗 |
| `confirmText` | 否 | 主按钮文案，缺省「确认」 |
| `dismissText` | 否 | 次按钮文案，缺省「取消」；critical 弹窗没有次按钮，此字段无效 |
| `once` | 否 | 默认 true：点过弹窗按钮（取消也算）后不再弹；false 则每次打开都弹 |
| `priority` | 否 | normal（默认）或 critical。critical 是阻断式弹窗：只有主按钮，点外部、按返回键都关不掉 |
| `startAt` / `endAt` | 否 | 排期窗口（闭区间），窗口外不弹，缺省不限制 |
| `minVersion` / `maxVersion` | 否 | 版本定向，只弹给版本号落在区间内的安装 |

时间字段三种写法都认：`"2026-10-15 09:00:00"`（推荐，按设备本地时间）、ISO 带时区（`"2026-10-15T09:00:00+08:00"`，换算到用户时区比较）、纯日期（作 `startAt` 是当天 0 点，作 `endAt` 是当天 23:59:59，含全天）。写错格式不会杀死整条通知，该字段按缺省处理——所以日期写错的表现是排期悄悄失效，推送前最好本地跑一遍 `python3 scripts/check_notice.py` 预检。

带 `link` 的通知建议同时给旧版本留退路：要么用 `minVersion` 定向到支持跳转的版本（如 `1.2.0-beta.4`），要么同时写 `url` 让旧版本开浏览器。都没有时，旧版本用户点主按钮只会关闭弹窗，正文里的文字路径就是唯一指引。

## 客户端怎么决定弹哪一条

每次打开 App 或回到前台，客户端按固定顺序过滤：排期窗口、版本定向、去重（once 加本地已读）。命中的通知全部进入弹窗队列，与修复类更新的弹窗合并后按优先级排序——修复类更新最高，critical 通知次之，普通通知最后，同级按文件里给的顺序。一次只弹一个，处理完自动弹下一个，直到队列清空；弹窗只在课表主界面空闲时插入，引导页、设置与关于等面板和编辑流程中不会出现，回到课表后待弹的会自动出现。

去重记录存在本地，上限 32 条并随文件内容自动清理。App 被强杀、用户没来得及点按钮时视为未读，下次打开还会弹。

排期判断的"现在"走 `KbClock.now()`，和课表模块同源——开发者模式的时间旅行会平移它，测时间窗不用等到点。拉取失败（404、断网、超时）一律静默跳过，不影响启动流程，也不影响更新提醒。

## 运维注意

`once: false` 的通知每次冷启动都会重新进队列，文件不删就永远弹；`once: true` 的新用户也会弹一次。公告过期就删文件，或者一开始就写上 `endAt` 让它自动过期。

多条命中的通知会排队依次弹出（critical 在前、同级按文件顺序），一次会话内会全部处理完。`once: false` 的条目下次冷启动还会重新进队列——常驻条目一多，用户开场就要连着点完一串弹窗，仍建议用 `startAt`/`endAt` 错开档期，别堆常驻。

想改文案又不让用户重弹，就把 `id` 写死；反过来想强制重新触达，换掉 `id` 即可。

通知内容随仓库公开，且会经第三方镜像转发，属于明文广播，别放隐私或时效敏感的信息。文件保持在几 KB 以内，`message` 别塞太长。
